Lesson 1

The AI family tree

Acronyms first

AIArtificial Intelligence. Machines doing tasks that normally need human intelligence. MLMachine Learning. A way of building AI where the system learns rules from examples instead of being hand-coded. DLDeep Learning. ML that uses neural networks with many layers. GenAIGenerative AI. AI that creates new content: text, images, code, audio. LLMLarge Language Model. The deep learning model behind ChatGPT, Claude and Gemini. Trained on huge amounts of text. NNNeural Network. Layers of tiny calculators that pass numbers forward. The building block of deep learning. The diamond is a weight, one dial inside it; the symbol stays with weights for the rest of the course. NLPNatural Language Processing. AI that works with human language. CVComputer Vision. AI that works with images and video.

The nesting

Each ring sits inside the one before it. Say it as a sentence: "GenAI is a kind of deep learning, which is a kind of machine learning, which is a kind of AI."

AI any machine doing "smart" tasks, including old rule-based systems like a chess program with hand-written rules
Machine learning learns patterns from examples, e.g. a spam filter trained on emails marked as spam
Deep learning neural networks with many layers; best for messy data like images, audio and text
Generative AI today LLMs for text and code, diffusion models for images

Watch out: not all AI is ML (a rules-based chatbot is AI but not ML), and not all ML is deep learning (a simple price predictor can be ML with no neural network).

A neural network, simply

1. InputNumbers go in. A picture becomes pixel values; text becomes numbers too (Lesson 2 explains how).
2. Layers of weightsEach tiny unit multiplies its inputs by "weights", adds them up, passes the result on. Many layers stacked = "deep".
3. OutputA guess comes out: "cat 92%". Training means showing millions of examples and nudging the weights until mistakes shrink.

The weights are the "knowledge". When people say a model has "70 billion parameters", parameters means weights. Bigger usually means more capable but costlier to run.

Three ways ML learns

SupervisedLearns from labeled examples. "This email is spam, this one is not." Most business ML is this.
UnsupervisedNo labels. Finds structure on its own, like grouping customers into clusters you did not define.
ReinforcementTrial and error with rewards. Learns by doing, like a game-playing agent. LLMs are polished with a version of this, RLHF, in Lesson 2.

Where the words you hear fit

  • Algorithm: a recipe of steps. Every ML method is an algorithm; not every algorithm is ML.
  • Model: what you get after training. The algorithm plus the learned weights, ready to make predictions.
  • Training vs inference: training is learning (slow, expensive, done once). Inference is using the model to answer (every time you send a prompt).
  • NLP and CV are application areas, not rings in the tree. An LLM is deep learning applied to NLP.

Real-world example: a data security product

Data security products use ML to classify data (supervised: "this field is a credit card number"), spot unusual behavior (unsupervised: "this access pattern is not like the others") and now LLMs to read documents and explain findings. Knowing which type of learning a feature relies on tells you what data it needs and how it can fail.

Likely interview question

"What is the difference between AI, ML and generative AI?"

Answer in 20 seconds: AI is the goal. ML is the main way we reach it today, by learning from data instead of hand-written rules. Deep learning is ML with neural networks, and generative AI is deep learning that produces new content, like an LLM producing text. Then give one example for each.

Lesson 2

How LLMs actually work

Terms first

TokenThe chunk of text an LLM reads and writes. Often part of a word. Costs and limits are counted in tokens. Symbol: a chip. Context windowHow much text one request can hold: instructions, the conversation so far, attached documents and the answer. Symbol: brackets. EmbeddingA list of numbers that captures the meaning of a piece of text. Similar meaning, nearby numbers. Symbol: a point with a halo. HallucinationA fluent, confident answer that is wrong or made up. SFTSupervised Fine-Tuning. Teaching a pretrained model the assistant format from human-written example conversations. RLHFReinforcement Learning from Human Feedback. Humans rank answers; the model is nudged toward the ones people prefer. TransformerThe neural network design behind every modern LLM. The "T" in GPT. Prompt injectionText inside a document or web page that tricks the model into following it instead of its real instructions.

One job: predict the next token

Strip everything else away and an LLM does one thing: given the text so far, guess the next token. Then it adds that token and guesses again. Answers, code and arguments all come out of this loop.

Thequickbrownfoxjumps→over 62%into 11%high 4%

Autocomplete at enormous scale. The percentages are made up for the example; the shape is real. The model picks a likely token, not a verified fact. Keep that in mind for the hallucination card below.

Tokens

Unbelievable=3 tokens
  • Rules of thumb for English: about 4 characters per token, and 1,000 tokens is roughly 750 words.
  • Pricing and limits are per token, for input and output separately. Output tokens usually cost more.
  • Other scripts and code often need more tokens for the same meaning, so they cost more.
  • Tokens are why models sometimes fail at spelling or counting letters: they never see the letters, only the chunks.

Context window

One request's working memory. Everything below has to fit, and the model forgets it all when the request ends.

Instructions
Conversation so far
Documents you attach
Answer
  • Sizes range from a few thousand tokens to over a million, depending on the model. Bigger windows cost more per request and run slower.
  • When a chat outgrows the window, the app drops or summarizes older turns. That is why long chats "forget".
  • Common question: a "memory" feature in a chat app is the app saving notes and pasting them back into the window next time. The model itself did not learn anything.

Embeddings

Text goes in, a list of numbers comes out. Texts with similar meaning land close together. Plotted in two dimensions it looks like this:

  • This is how semantic search works: embed the query, find the nearest stored texts, even when no words match.
  • It is the engine under RAG and vector databases, which come in Lesson 5.
  • Inside the model, the first step for every token is also an embedding. The map above is that same idea used on whole sentences.

How a chat model is trained

1. PretrainingPredict the next token across trillions of tokens of text. No human labels; the next word is the label. People call this self-supervised. This is where almost all the knowledge comes from.
2. SFTSupervised fine-tuning. Humans write example conversations. The model learns to behave like an assistant instead of continuing random web text.
3. RLHFHumans rank candidate answers. A reward model learns those preferences. Reinforcement learning nudges the weights toward answers people prefer.

So "is ChatGPT supervised or reinforcement learning?" has the answer "both, in stages", and the same pipeline shape applies to Claude and Gemini. During your chat the weights are frozen: the model is doing inference, not learning. Whether your conversations are used in a provider's future training depends on that provider's policy and your account settings, so check before stating either way in an interview.

Why hallucinations happen

Causes
  • The model predicts plausible text. It does not look facts up unless an app gives it a tool.
  • Training rewards fluent, helpful answers, so a confident guess can beat "I don't know".
  • Gaps and errors in the training data, and anything after the knowledge cutoff.
  • Long or ambiguous prompts where the model fills gaps with likely-sounding detail.
What helps
  • Ground it: give it the relevant documents and ask it to cite them (RAG, Lesson 5).
  • Ask for uncertainty: "say you are not sure if you are not".
  • Tools for facts and math: search, calculators, databases.
  • Design for verification: show sources, make checking one click, keep a human in the loop for high-stakes outputs.

What an LLM can and cannot do reliably

Reliable
  • Summarize, rewrite, translate, change tone.
  • Classify and extract structured fields from messy text.
  • Draft code, emails, specs, first versions of anything.
  • Explain a concept at any level.
Not reliable on its own
  • Facts after its training cutoff.
  • Exact arithmetic, counting, dates.
  • Remembering you between sessions.
  • Giving the same answer twice (outputs vary run to run).
  • Telling instructions apart from data. Text inside a file it reads can hijack it: prompt injection.

Real-world example: a data security product

When an LLM reads customer files, four things follow: the file content is untrusted input (prompt injection), personal data inside it may leave the customer's boundary when sent to a model provider, any finding the model writes could be a hallucination and needs a source, and token costs scale with how much text you feed it. A designer who can name these gets taken seriously.

Likely interview question

"Why do LLMs hallucinate, and how would you design around it?"

Short answer: because the model generates likely text rather than looking facts up, and because training rewards confident, fluent answers. Design around it by grounding answers in retrieved documents with citations, letting the model say it is unsure, routing facts and math to tools, and making verification cheap for the person reading the output.

Lesson 3

The AI landscape in 2026

Terms first

Frontier modelThe most capable models from the leading labs at a given moment. The bar moves every few months. Open weightsThe trained weights are published, so anyone can download and run the model on their own servers. Open sourceStrictly, weights plus training code and data. Most "open" models are open weights only. Reasoning modelAn LLM that writes thinking tokens before its answer. Slower, costlier, better on multi-step problems. Knowledge cutoffThe date the training data ends. The model knows nothing after it unless an app gives it tools. MultimodalA model that takes more than text: images, audio, video. SLMSmall Language Model. A smaller, faster, cheaper model for narrow tasks, sometimes run on a phone or laptop. APIApplication Programming Interface. The way an app calls a model over the internet.

The players

Model names and version numbers change every few months. Remember the labs and their model families; check the current version before an interview.

AnthropicClaudeClosed, via API and apps
OpenAIGPT and the "o" reasoning seriesClosed, via API and apps
Google DeepMindGeminiClosed, via API and apps
MetaLlamaOpen weights
MistralMistral modelsOpen weights and hosted
DeepSeekDeepSeek modelsOpen weights
AlibabaQwenOpen weights
xAIGrokClosed, via API and apps

Closed model vs open weights

Closed, via API
  • Usually the most capable, with the newest features.
  • Your text goes to the provider's servers for processing. Check their data retention and training terms.
  • Zero upkeep: no servers, no model updates to manage.
  • You depend on their pricing and deprecation schedule.
Open weights, self-hosted
  • Data stays inside your own boundary. Regulated customers often require this.
  • You can fine-tune and control versions.
  • You pay for servers and the people to run them.
  • Typically a step behind the frontier in capability.

The "open source shift" means open-weight models went from toys to good enough for many production tasks, which changed the buy-vs-host decision.

Reasoning models

Prompt→AnswervsPrompt→Thinking tokens: plan, check, revise→Answer
  • The model "thinks out loud" to itself before answering. Those tokens cost money and time, so expect slower, pricier responses.
  • Big gains on multi-step work: math, code, planning, analysis. Little gain on simple rewrites or classification.
  • Many models now expose this as a setting: a thinking toggle or an effort level. The product decision is when to spend it.

The knowledge half-life problem

Training data ends (cutoff)→Model released months later→Used for a year or more→Gap grows every day
  • A model has no idea what happened after its cutoff. It will still answer, which is a hallucination risk.
  • Fixes that do not need retraining: give it search, give it your documents (RAG), or pass fresh facts in the prompt.
  • It applies to people too. Specs you memorize today will be stale in six months. Interviewers rate how you reason and check over what you recall.

Choosing a model

CapabilityCan it do the task well enough? Measure on your own examples (an "eval"), not on headlines.
CostPrice per token, times how many tokens the feature uses per user. Lesson 6 does the math.
SpeedTime to first token and tokens per second. A chat tolerates seconds; an autocomplete does not.

Common pattern: a small, fast model for routing and classification, a frontier model for the hard step, a reasoning mode only where the stakes justify the wait. Multimodal models add images and audio as input, which matters for screenshots, scans and calls.

Real-world example: a data security product

A data security product sits on a hard version of this choice: customers care where their data goes, so open-weight models inside the customer's cloud are attractive, while the best classification and explanation may come from a frontier API. A designer can shape this by making data flows visible and letting customers pick where processing happens.

Likely interview question

"How would you choose between a frontier API model and an open-weight model for a security product?"

Start from the customer's data boundary and compliance needs, then capability on real examples, then cost and speed. Often the answer is both: a self-hosted model for anything touching raw customer data, a frontier model for tasks that only see redacted or summarized text.

Lesson 4

Prompting as structured thinking

Terms first

PromptEverything you send the model in one request: instructions, context, examples, the question. System promptThe standing instructions an app sends before the user's message. Usually invisible to the user. Where a product's "personality" and rules live. Zero-shotAsking with no examples. Few-shotAsking with two or three worked examples in the prompt. The model copies the pattern. CoTChain of Thought. Asking the model to reason step by step before giving the answer. ToTTree of Thought. Asking the model to branch into several approaches, judge them, and continue down the best one. Role prompting"You are a security analyst..." Sets vocabulary, priorities and tone. Adds no knowledge. Structured outputAsking for a fixed format such as JSON so software can read the answer reliably.

Anatomy of a prompt that works

Role who the model is and who it is talking to
Task one clear verb: summarize, classify, draft, compare
Context the documents, data and background it needs. Fresh facts go here, not in its memory.
Constraints length, tone, what to avoid, what to do when unsure
Examples two or three input and output pairs (few-shot)
Output format headings, a table, JSON fields, a word limit

Most bad outputs trace back to a missing block. Before blaming the model, check which block is empty. A prompt is a brief for a very literal colleague.

Chain of thought

Without

"Is this access pattern suspicious? Answer yes or no."

The model commits in its first token and then defends it.

With

"List what is normal for this user, list what is different today, weigh them, then answer yes or no with one reason."

The steps are tokens. Tokens are the model's only scratchpad, so writing them out improves the answer.

  • Reasoning models (Lesson 3) do this on their own in hidden thinking tokens. For other models you ask for it.
  • Use it for judgment, math, multi-step analysis. Skip it for simple rewrites: more tokens, no gain.
  • For you, not just the model: write the steps before the verdict when you critique a design. Same trick, same reason.

Tree of thought

  • Ask for three different approaches, then ask the model to score each against your criteria, then develop the winner.
  • Good for planning, naming, information architecture options, anything where the first idea is rarely the best.
  • Costs several calls or a long prompt. Use it when the decision matters.

Role prompting, and its limits

  • A role changes vocabulary and what the model prioritizes. "Act as a CISO reviewing this plan" gets risk-first language.
  • It does not add knowledge or accuracy. "You are a world expert" does not make the facts right.
  • Stronger version: describe the audience too. "Explain to a product designer with no ML background" beats "be simple".

Pitfalls

Leading questions

"This design is accessible, right?" The model tends to agree. Ask for the strongest case against instead.

Pasted content

Anything you paste can contain instructions the model follows (prompt injection, Lesson 2). Separate data from instructions and say which is which.

No format

Software reading free text breaks. Ask for JSON with named fields when the output feeds another step.

One giant prompt

Split into steps and check between them. That is the "loop engineering" idea in Lesson 5.

Real-world example: a data security product

In an AI feature, the system prompt and the output format are product surface, as much as the screen is. A designer who can write the prompt spec (role, constraints, format, failure behavior) and test it on real examples shapes the experience more than one who only draws the panel the answer lands in.

Likely interview question

"How would you get consistent output from an LLM feature?"

A clear system prompt with role, constraints and a fixed output format, two or three examples, step-by-step reasoning for judgment calls, a small set of real test cases you run every time the prompt changes, and a fallback for when the model is unsure.

Lesson 5

Agents, RAG, vector databases, MCP

Terms first

AgentAn LLM given a goal, tools, memory and a loop: think, act, observe, repeat until done. Tool / function callingThe model asks the app to run a named function with arguments. The app runs it and sends the result back. Symbol: a hexagon with a plus. RAGRetrieval-Augmented Generation. Fetch the relevant pieces of your documents and put them in the prompt before the model answers. Symbol: a document page. Vector databaseA store for embeddings that finds the nearest ones fast. The search engine under RAG. MCPModel Context Protocol. An open standard for connecting models to tools and data, so one connector works in many apps. Loop engineeringDesigning the iterate-check-correct loop around the model, instead of hoping one prompt gets it right. Custom GPTA packaged prompt plus files plus optional actions, shared inside ChatGPT. Claude Projects are the similar idea. LatencyDelay before and during a response. The hard problem in voice agents.

What an agent is

Goal→Think (LLM)→Act: call a tool→Observe result→Done? If not, think again
BrainThe LLM. Decides what to do next from the goal and what it has seen so far.
MemoryThe context window for now, plus notes or a database for anything that must survive the request.
ToolsFunctions it may call: search, read a file, query a database, send an email. Each one is a permission you granted.

A chatbot answers once. An agent keeps going. That loop is the difference, and it is also where the risk lives.

Function calling, step by step

1 The app tells the model which tools exist, with a name, a description and the shape of the arguments.
2 The model answers with a structured request: call lookup_user(email).
3 The app runs the function. The model never runs code itself.
4 The app sends the result back into the context. The model continues or answers.

Design lever: the tool descriptions are copy. Vague descriptions produce wrong calls, exactly like vague labels produce wrong clicks.

RAG, in two rows

Set-up

Your documents→Split into chunks→Embed each chunk→Store in a vector database

Every question

Question→Embed it→Find nearest chunks→Put them in the prompt→Answer with citations
  • Use RAG for facts that are private, large or changing: policies, tickets, contracts, your own data.
  • Fine-tuning is the other option people confuse it with. Fine-tuning teaches style and format by changing weights. It is a poor way to add facts.
  • RAG fails when chunks are cut badly, retrieval misses, or the model ignores the chunks. Showing the sources lets the reader catch all three.

Vector databases

  • They store embeddings plus metadata (source, date, owner) and answer "which stored items are closest to this one".
  • Names you may hear: Pinecone, Weaviate, Chroma, and pgvector, which adds this to a normal Postgres database.
  • Security point: access control must apply to chunks. If a user cannot open the document, retrieval must not surface its chunks either.

MCP, the connector standard

Claude or another client↔MCP↔Server for Slack, GitHub, a database, your product...
  • Introduced by Anthropic in late 2024, now used across many tools. Think of it as a shared plug: build one server for your product and any MCP client can use it.
  • A server exposes tools (actions), resources (data) and prompts. The client's model decides when to call them.
  • The "connectors" you see in Claude are MCP servers. Claude Projects and Skills add an agentic layer on top.

Loop engineering vs prompt engineering

Prompt engineering tunes one request. Loop engineering designs the system around it: break the job into steps, check each output against rules or a second model, retry or escalate when a check fails, and keep a test set (an eval) so you know when changes help. Agents are loop engineering with tools inside the loop.

No-code builders and voice, briefly

  • n8n and Make.com: visual workflow builders with LLM steps, triggers and tool calls. Botpress and similar for chatbots with RAG over your files.
  • Voice agents (Vapi, Bland, Retell, ElevenLabs for voices) chain speech-to-text, an LLM and text-to-speech. The hard parts are latency, interruptions and phone connections.
  • Custom GPTs and GPT Actions: a packaged prompt and files, plus function calls to outside APIs.

Real-world example: a data security product

An agent that reads data stores to find sensitive data needs least-privilege tools, a log of every action, and a human approval step before anything destructive. Prompt injection inside a scanned file could otherwise turn into a tool call. The design questions are about permissions, visibility and undo.

Likely interview question

"How would you design the permissions for an AI agent inside a security product?"

Give it the fewest tools that complete the job, make read and write tools separate, show the user what it is about to do before any write, log everything, treat any file content as untrusted, and let admins scope which data it may touch.

Lesson 6

AI business basics

Terms first

Unit economicsWhat one user (or one query) costs you and earns you. Gross marginRevenue minus the direct cost of serving it. For AI products, model calls are a big part of that cost. Thin wrapperA generic prompt over someone else's model, with little else. Easy to copy. Vertical AIAI built deep into one industry's workflow and data, such as legal, healthcare or security. MoatWhat stops competitors from copying you once they see what you did. Outcome-based pricingCharging per result (a resolved ticket) instead of per seat or per use. B2B / B2C / B2B2CSelling to businesses, to consumers, or to businesses who serve consumers with it. COGSCost of Goods Sold. For AI software, mostly model calls, hosting and support.

Token math, worked example

Prices below are illustrative, not quotes. Check the provider's page for current rates. The method is what matters.

Per query 3,000 input tokens (prompt, documents) + 500 output tokens
Example rates $3 per million input tokens, $15 per million output tokens
Cost per query 3,000 ÷ 1,000,000 × $3 = $0.009, plus 500 ÷ 1,000,000 × $15 = $0.0075, total about $0.0165
Per user per month 200 queries × $0.0165 = about $3.30
Margin check At a $20 subscription that is roughly 16% of revenue on model calls alone, before hosting and support. At $5 it does not work.
  • Levers: a smaller model for easy steps, shorter prompts, caching repeated context, limits per user, batching background jobs.
  • Output tokens usually cost several times more than input. Long answers are expensive; so are reasoning tokens.

Pricing models

SubscriptionPredictable for the customer. You carry the risk of heavy users. Needs usage caps or tiers.
Usage-basedCost tracks revenue. Harder to budget for buyers, and discourages use.
Per outcomeCharge per resolved ticket or per closed deal. Great alignment, hard to measure fairly.

Thin wrapper vs vertical AI

Thin wrapper
  • A prompt and a chat box over a frontier API.
  • Any competitor, or the model provider's next feature, can copy it in a week.
  • No data advantage, no workflow lock-in.
Vertical AI
  • Lives inside one industry's workflow: the tools people already use, the formats they need, the rules they must follow.
  • Learns from proprietary data the public model never saw.
  • Earns trust through compliance, accuracy on the domain's hard cases, and integrations.

Building a moat

  • Proprietary data: outcomes and labels only you collect, which make your models or evals better over time.
  • Workflow lock-in: once a team's process runs through you, switching costs are real.
  • Distribution: an existing customer base, partners, marketplaces.
  • Trust and compliance: certifications, audits, data residency, a track record. Slow to earn, slow to copy.
  • Not a moat: "we use AI". Everyone does.

Business models and competitive response

  • Agent-as-a-service: sell the work done, not the software. Marketplaces: let others build on your platform.
  • Startups usually win by going deeper on one workflow and moving faster. Incumbents respond with distribution, bundling and trust, and often buy the startup.
  • B2B is where most AI revenue is today; B2B2C puts your AI inside someone else's product for their customers.

Real-world example: a data security product

Security is a trust business, which makes trust and compliance the natural moat. Costs scale with data volume scanned, so the design question is what to run with cheap classifiers and what to send to an LLM. Being able to sketch the per-customer cost of a feature puts a designer in the pricing conversation.

Likely interview question

"What makes an AI product defensible?"

Data others do not have, a workflow people depend on, distribution, and trust. The model itself is rented and will be matched. Then give an example from the company's domain.

Lesson 7

Responsible AI and privacy

Terms first

BiasSystematic unfairness in outputs, usually inherited from the data or the way a goal was set. FairnessComparable outcomes and error rates across groups of people. ExplainabilityBeing able to say why the system produced a result, in terms a person can check. PIIPersonally Identifiable Information. Names, emails, IDs, anything that points at a person. DPDPDigital Personal Data Protection Act, India, 2023. India's data privacy law. GDPRGeneral Data Protection Regulation, European Union, in force since 2018. CCPACalifornia Consumer Privacy Act, 2020, expanded by the CPRA (California Privacy Rights Act). Data residencyWhere data is physically stored and processed. Some customers and laws require it to stay in a country or region. GuardrailsChecks around the model: input filters, output filters, allowed actions, human approval. Where bias gets in

Data who is over- or under-represented in the training set, and whose past decisions it recorded
Labels what humans marked as "good", with their own blind spots
Objective what the system was optimized for, such as speed over accuracy for one group
Deployment who it is used on versus who it was tested on
  • Test error rates per group, not just overall accuracy. A 95% accurate system can be 70% for one group.
  • For an LLM feature: run the same prompt with names, locations or languages swapped and compare outputs.

Responsible AI in practice

Before launch
  • Evals on real, varied examples, including hard and adversarial ones.
  • Red teaming for prompt injection, data leakage and harmful outputs.
  • Decide which decisions stay with a person.
In the product
  • Show sources and confidence; make "why" one click away.
  • Guardrails on inputs, outputs and actions.
  • Easy feedback and a log you can audit.
  • Clear copy about what the AI does with data.

Privacy in an AI system: follow the data

User→Your app→Model provider→Logs, caches, training sets?

Five questions answer most privacy reviews:

  • What exactly is sent to the model? Can PII be redacted or masked first?
  • Is it retained by the provider, for how long, and is it used for training? (Business API terms usually differ from consumer apps.)
  • Where is it processed and stored? (Residency.)
  • Who inside your company can see prompts and outputs in logs?
  • Can a user see, export and delete what you hold about them?

The three laws, key ideas only

This is the shape of each law, not legal advice. Check current text before relying on a detail.

DPDP (India, 2023)Consent-based processing of digital personal data with stated purposes. Organizations that decide how data is used are "Data Fiduciaries" with duties such as security safeguards and breach notification. A Data Protection Board handles complaints. Rules for enforcement have been rolling out since the Act passed.
GDPR (EU, 2018)Needs a lawful basis for every use of personal data. People get rights to access, correct, delete and port their data. High-risk processing needs an impact assessment (DPIA). Breaches must be reported within 72 hours. Fines can reach 4% of global turnover.
CCPA / CPRA (California)Applies to businesses above size or data thresholds. Residents can know what is collected, delete it, and opt out of its sale or sharing. CPRA added a dedicated enforcement agency and limits on "sensitive" data.

Common thread across all three: a stated purpose, minimal data, people's rights over their data, and accountability when it leaks. An AI feature that sends raw customer text to a third-party model touches every one of those.

Designing for trust

  • Make the data map visible: what goes where, in the product, not just in a policy page.
  • Redact before sending. Show the user that it happened.
  • Give retention controls and a real delete.
  • Write consent copy a person can understand in ten seconds.

Real-world example: a data security product

For a data security company, this lesson is the product. Customers buy the ability to find and protect sensitive data under exactly these laws, so the design work is making discovery, classification and remediation flows that security teams trust and can use to prove compliance.

Likely interview question

"How would you make an AI feature privacy-safe by design?"

Send the minimum: redact or summarize before the model sees it. Pick where processing happens based on the customer's residency needs. Make retention and deletion real and visible. Show sources so findings can be verified. Log and limit what the AI can do, and test it against injection and leakage before launch.

Mock interview

Ten questions, answer out loud first

Say your answer in under 30 seconds before opening the strong answer. The best answers name the concept, give one example, and end with what you would do as a designer.

1. What is the difference between AI, machine learning and generative AI?

AI is the goal: machines doing tasks that need intelligence. Machine learning is the main way we get there now, by learning from examples instead of hand-written rules. Deep learning is machine learning with neural networks. Generative AI is deep learning that produces new content, like an LLM writing text. Example: a spam filter is ML; ChatGPT is generative AI.

2. How does an LLM actually work?

It predicts the next token, over and over. It was pretrained on huge amounts of text, then fine-tuned on example conversations, then polished with human feedback. It only sees the context window of one request, so anything it needs to know now has to be in the prompt or in its training. That is why it can be fluent and wrong at the same time.

3. Why do LLMs hallucinate and how would you design around it?

Because they generate likely text rather than looking facts up, and training rewards confident answers. I would ground answers in retrieved documents with citations, let the model say it is unsure, route facts and math to tools, and make verification one click for the reader.

4. What is RAG and when would you use it instead of fine-tuning?

Retrieval-Augmented Generation: embed your documents, find the chunks closest to the question, and put them in the prompt before answering. Use it for private, large or changing facts. Fine-tuning changes the weights to teach style or format; it is a poor way to add facts and it goes stale.

5. What is an AI agent?

An LLM with a goal, tools, memory and a loop: think, act, observe, repeat until done. A chatbot answers once; an agent keeps working. The design questions are permissions, visibility of what it is about to do, logging and undo.

6. What is MCP?

Model Context Protocol, an open standard for connecting models to tools and data. Build one MCP server for your product and any MCP client, like Claude, can use it. The connectors in Claude are MCP servers.

7. How would you choose a model for a feature?

Start from where the data may go: customer boundary and compliance decide between a self-hosted open-weight model and a frontier API. Then capability on our own test examples, then cost per query times volume, then speed. Often a small model for routing and a frontier model for the hard step.

8. What makes an AI product defensible?

Not the model, which is rented. Proprietary data, a workflow people depend on, distribution, and trust. In security, trust and compliance are the moat.

9. How would you make an AI feature privacy-safe by design?

Send the minimum and redact first, choose processing location by residency needs, make retention and deletion real, show sources, limit and log what the AI can do, and red-team it for injection and leakage before launch. I would map it against DPDP, GDPR and CCPA with the security team.

10. What is prompt injection and why should a designer care?

Text inside something the model reads that hijacks its instructions. For any product that reads customer files, file content is untrusted input. Designers own the moments where the agent shows what it is about to do, asks for approval, and separates data from instructions.

Three habits for the room

  • Expand acronyms the first time you say them. It shows you know what they mean, not just the letters.
  • When you are not sure, say what you would check and how. Interviewers rate reasoning over recall.
  • Bring every answer back to the user and the designer's role. That is the job you are interviewing for.
